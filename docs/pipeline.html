The pipeline in diagrams

One overview, then a zoomed-in diagram per stage. Each diagram says where its code is. The diagrams are drawn with Mermaid when the page opens in a browser.

Conventions in every diagram:

  • Rounded boxes are steps, diamonds are decisions, cylinders are stored data.
  • Every fact is yes / no / unknown. A step that can't decide leaves unknown and writes a review item; nothing defaults to "no".
  • Every external call goes through one cache (core/cache.py), so a re-run is free and gives the same answer.

Contents:

  1. Overview
  2. Extraction: notice PDFs to roster and seats
  3. Companies House: fetching officer records
  4. Deduplication: mentions to people
  5. Classification: roles and organisations
  6. Web search: one cited question
  7. Recommendations: reconcile and score
  8. Evidence freshness: is each fact recent enough?
  9. Gates and publishing
  10. Modifications: analyst decisions
  11. Caching, logging and the nightly run

1. Overview

flowchart TD
    pdfs[("Notice PDFs<br/>data/notices/")]
    policy[("config/policy.yaml")]
    dec[("Analyst decisions<br/>append-only")]

    subgraph run["One run: state/pipeline.py"]
        direction LR
        ex("1 Extract<br/>roster, seats") --> ch("2 Companies House<br/>officer records")
        ch --> dd("3 Deduplicate<br/>mentions to people")
        dd --> cl("4 Classify<br/>roles, listings, firm-site roles")
        cl --> sc("5 Score<br/>FOR / AGAINST / REVIEW")
        sc --> fr("6 Evidence freshness<br/>dates every citation, flags stale ones")
        fr --> gates{"Gates<br/>G1 to G4"}
    end

    pdfs --> ex
    policy --> sc
    dec --> dd
    dec --> sc

    llx(["LlamaExtract"]) -.-> ex
    chapi(["Companies House API"]) -.-> ch
    chapi -.-> dd
    claude(["Claude + web search"]) -.-> cl

    gates -->|"all pass"| staged["staged"]
    gates -->|"any fails"| held["held"]
    staged -->|"--publish"| pub[("Published run<br/>pointer")]
    held -.->|"pointer unchanged:<br/>last votes stand"| pub

    pub --> cli("pennant votes / show /<br/>review / history")
    pub --> evalx("pennant eval<br/>vs eval/gold/")
    cli --> mods("merge / split /<br/>set-fact / undo")
    mods --> dec

Each run writes its own rows (run_outputs) and never edits an earlier run, so any two runs can be diffed (pennant diff) and a bad run never replaces published votes. Section 9 covers the analyst loop at the bottom; section 11 covers the cache, logs and nightly job.

2. Extraction

Code: extract/validate.py (stage), extract/llamaextract.py (the job), extract/meeting.py (cross-checks), evidence/grounding.py (quotes on pages). Card M1. 

flowchart TD
    start(["For each PDF in data/notices/"]) --> key("Meeting key from the filename<br/>Tesco_2026_Notice_of_AGM.pdf to tesco")
    key --> cache{"LlamaExtract answer cached?<br/>key: PDF hash + schema + config"}
    cache -->|"yes"| job[("Job JSON<br/>fields + page citations")]
    cache -->|"no, recording in tests/fixtures"| seedc("Seed cache from the recording") --> job
    cache -->|"no, offline"| none["No extract: stage error, review item"]
    cache -->|"no, live"| budget{"Already recorded once?"}
    budget -->|"yes"| stop["BudgetError: ask expert<br/>no second paid run"]
    budget -->|"no"| live("Run one agentic job<br/>cite_sources: true") --> job
    live -.-> calls[("model_calls<br/>prompt, response, credits")]

    job --> parse("Parse: meeting, directors,<br/>appointments, each with page citations")
    parse --> pages("Read PDF text per page<br/>PyMuPDF")
    pages --> meet{"Company number and AGM date<br/>found in the PDF text?"}
    meet -->|"no"| merr["Stage error"]
    meet -->|"yes"| gap{"Resolution numbers<br/>contiguous?"}
    gap -->|"no"| g1["Problem for gate G1"]
    gap -->|"yes"| ground("Ground every quote on its cited page<br/>then the pages either side:<br/>exact, normalised, fuzzy 95+")
    ground --> found{"Quote found?"}
    found -->|"no"| drop["Drop the appointment<br/>review item: ungrounded"]
    found -->|"yes"| keep("Keep it, with notice evidence:<br/>doc, page, quote")
    keep --> out[("Outputs: meeting, roster entry per director,<br/>seat per appointment, plus the issuer seat")]

Rules worth knowing: only people named in election or re-election resolutions are on the roster; "Chair: Barratt Redrow plc and ICE Clear Europe" is two appointments; tense (past, current, future) comes from the notice's wording.

3. Companies House

Code: ch/client.py (client and stage), ch/parse.py (parsers). Card M3. 

flowchart TD
    start(["For each meeting"]) --> ol("GET /company/number/officers<br/>every page")
    ol --> ok{"Officer list ok?"}
    ok -->|"no: outage"| una["Review item ch_unavailable<br/>gate G2 will hold the run"]
    ok -->|"yes"| each("Each director on the list")
    each --> inoff{"In office on the AGM date?"}
    inoff -->|"resigned in the year before"| recent("Keep the issuer record only<br/>explains an unmatched name")
    inoff -->|"older or not a director"| skip["Ignore"]
    inoff -->|"yes"| apps("GET /officers/id/appointments<br/>every page")
    apps --> types("Company profile for each appointment<br/>live since the earliest AGM:<br/>its company type")
    types --> out[("officer outputs<br/>name, DOB month and year, appointments")]
    recent --> out

    subgraph http["Every CH request"]
        direction TB
        c{"Cached and still fresh?<br/>good until 23:59 that day"} -->|"yes"| hit["Use it"]
        c -->|"no"| get("GET, at most 2 per second") --> st{"Status"}
        st -->|"200 / 404"| store["Cache it: ok / not_found<br/>same answer only moves last_fetched"]
        st -->|"429 / 5xx"| retry["Retry with backoff, 5 tries"]
        retry -->|"still failing"| down["unavailable: never cached,<br/>never an exception"]
    end

An outage becomes unavailable, never "no seats": a director whose records can't be read scores REVIEW, and gate G2 holds the run.

4. Deduplication

Code: dedup/cluster.py (stage), dedup/anchor.py (anchor and expand), dedup/names.py, dedup/tfidf.py. Card M4. Target: 50 notice mentions become 47 people. 

flowchart TD
    m(["Each roster entry: a name in one notice"]) --> rank("Rank the issuer's directors in office on the AGM date<br/>same surname, titles and honours stripped,<br/>first names scored by 3-gram TF-IDF")
    rank --> win{"Clear winner?<br/>score and margin"}
    win -->|"yes"| anchor["Anchor: mention to CH officer<br/>with CH evidence"]
    win -->|"close race"| psp["Review item<br/>possible_same_person"]
    win -->|"nobody in office"| former{"A former director<br/>clearly matches?"}
    former -->|"yes"| fanchor["Anchor to that record<br/>review item not_in_office<br/>seat will reconcile as stale"]
    former -->|"no"| unanch["Review item unanchored"]

    anchor --> search("Officer search on the CH name<br/>pages read until past the namesakes")
    fanchor --> search
    search --> dob{"Same DOB month and year?"}
    dob -->|"no"| ign["Ignore"]
    dob -->|"yes"| nm{"Name match"}
    nm -->|"exact"| link["Link the other record<br/>load its appointments"]
    nm -->|"variant or initial"| rv["Review item<br/>possible_same_person"]

    link --> uf
    anchor --> uf
    fanchor --> uf
    subgraph uf["Cluster: union-find over mentions and officers"]
        direction TB
        a1("Apply analyst must-links first") --> a2("Apply links in a fixed order")
        a2 --> a3{"Would join a<br/>cannot-link pair?"}
        a3 -->|"yes"| ref["Refuse the union<br/>review item"]
        a3 -->|"no"| join["Join"]
    end

There is no model here: identity comes from the issuer's officer list and the date of birth, and anything ambiguous goes to the analyst.

    subgraph C["Step 3: listed status onto seats"]

    subgraph D["Step 4: roles still unknown, firm's own site only"]
        direction TB
        p1("Seats that could count:<br/>current, listed not no,<br/>board seat, chair or executive unknown") --> p2("site_v1: find the firm's own website<br/>cited page must be on it and name the firm;<br/>never a news, data or registry site")
        p2 --> p3{"Own site found?"}
        p3 -->|"no"| p4["Review item site_not_found<br/>role stays unknown"]
        p3 -->|"yes"| p5("position_v2: role on the AGM date,<br/>search limited to that site;<br/>facts citing other sites dropped")

    end

    A --> B --> C --> D

A person's role is never looked up anywhere but the firm's own site, and a job title alone is never a board seat.

6. Web search

Code: classify/websearch.py (ask, validate), classify/backends.py (provider), classify/prompts.md (prompts), calllog.py (the call record). 

flowchart TD
    q(["A question: kind, prompt version, inputs"]) --> k("Cache key: prompt version + model + inputs")
    k --> c{"Cached answer<br/>under 7 days old?"}
    c -->|"yes"| ans[("Answer")]
    c -->|"no, offline"| off["No answer: unknown<br/>review item"]
    c -->|"no, live"| model("Call the model with web search<br/>max 5 searches;<br/>site-limited for role questions")
    model --> rec[("model_calls: prompt, response,<br/>outcome, latency, tokens")]
    model --> res{"Result"}
    res -->|"rate limit, network, 5xx"| unav["unavailable: unknown<br/>review item, not cached"]
    res -->|"bad key, search disabled"| raise["Run fails: expert fixes it"]
    res -->|"search error or no JSON"| rej["rejected: unknown<br/>review item, not cached"]
    res -->|"usable"| store("Cache it") --> ans

    ans --> v("validate: for each fact in the JSON")
    v --> v1{"Has a quote, and its URL is one<br/>the search returned in this response?"}
    v1 -->|"no"| dropf["Drop it: unknown<br/>review item web_unsourced"]
    v1 -->|"yes"| v2{"Role question: page on<br/>the firm's own site?"}
    v2 -->|"no"| dropf
    v2 -->|"yes or not a role question"| keepf["Keep it, with web evidence:<br/>URL, title, quote"]

Validation runs every time an answer is read, so a stricter rule applies to every cached answer without asking again. The quote itself is not checked against the page text: only that the page came back from the search.

7. Recommendations

Code: policy/stage.py (stage), policy/reconcile.py (seats against CH), policy/score.py (points and rules), core/tri.py (three-valued logic). Card M6. 

flowchart TD
    p(["Each person at each of their meetings"]) --> rc("Reconcile notice seats with CH on the AGM date")
    rc --> st{"Seat status"}
    st -->|"notice current, CH active"| s1["confirmed: board seat yes"]
    st -->|"CH resigned before the AGM"| s2["stale: current unknown"]
    st -->|"no CH appointment"| s3["contradiction: current unknown"]
    st -->|"non-UK org"| s4["ch_invisible: notice + web facts"]
    st -->|"notice says past"| s5["past: never counts"]
    st -->|"CH-only directorship"| s6["undisclosed: board yes,<br/>chair and executive unknown"]
    s1 & s2 & s3 & s4 & s5 & s6 --> pos("Fill unknown role facts from the<br/>firm's own site, section 5 step 4")
    pos --> sf("Apply analyst set-facts last")
    sf --> cnt("counted = board seat AND current<br/>AND listed AND identity")
    cnt --> pts("Points: 1 per counted seat, 2 per chair;<br/>one corporate group counts once, its best seat;<br/>an interval when facts are unknown")
    pts --> pr("points rule = non-executive here<br/>AND points over 4")
    cnt --> er("executive rule = executive at a listed board<br/>AND a counted seat in another group")
    pr & er --> v{"points rule OR executive rule"}
    v -->|"yes"| ag["AGAINST"]
    v -->|"no"| fo["FOR"]
    v -->|"unknown"| rv["REVIEW, listing the single facts<br/>that would settle it"]

The vote is FOR or AGAINST only if every way of filling in the unknowns agrees; that is why a REVIEW can always say which fact would settle it (pennant show, pennant review).

8. Evidence freshness

Code: evidence/freshness.py. Runs after scoring.

flowchart TD
    s(["Every Companies House and web citation<br/>on this run's people, seats and organisations"]) --> d("Date it: when the answer was last confirmed<br/>CH: the cache row's last fetch;<br/>web: its fetch date")
    d --> need("Date it must be checked on or after:<br/>today if the AGM is still ahead;<br/>the AGM date if it has been held;<br/>a record used at two meetings is held to the later")
    need --> q{"Last confirmed before that date?"}
    q -->|"yes"| flag["Review item stale_evidence<br/>the vote does not change"]
    q -->|"no"| ok["Fresh"]
    note(["Notice and analyst citations<br/>are never stale"])

A stale citation is a prompt to re-run live before relying on the vote; it never changes the vote by itself.

9. Gates and publishing

Code: state/pipeline.py. Card M7.1.

flowchart TD
    r(["Stages done"]) --> exc{"Any stage raised?"}
    exc -->|"yes"| failed["failed"]
    exc -->|"no"| g1{"G1 extraction:<br/>resolutions contiguous, and every quote<br/>behind an AGAINST still grounds"}
    g1 --> g2{"G2 Companies House:<br/>no outage, every issuer has officers"}
    g2 --> g3{"G3 churn, nightly runs only:<br/>no FOR to AGAINST flip without<br/>a changed input for that person"}
    g3 --> g4{"G4 completeness:<br/>every roster entry has a vote,<br/>every decision honoured"}
    g4 --> all{"All pass?"}
    all -->|"yes"| staged["staged"]
    all -->|"no"| held["held"]
    staged -->|"--publish"| pub[("Published pointer moves")]
    held --> keep["Pointer stays:<br/>yesterday's votes stand"]
    failed --> keep
    pub --> diff("Diff against the previous published run:<br/>each change tagged with its cause:<br/>a decision, a cache entry, a policy change")

A run's status is set once. Only a staged run, or an earlier published one for a rollback, can be published; database triggers refuse anything else.

10. Modifications

Code: cli.py and cli_changes.py (commands), state/decisions.py (append-only decisions), state/history.py. Card M8. 

flowchart TD
    a(["Analyst: merge, split, set-fact or undo"]) --> prev("Preview: what will be recorded,<br/>who it affects, their current vote")
    prev --> conf{"Record it? y/N<br/>-y skips the question"}
    conf -->|"no"| nothing["Nothing recorded"]
    conf -->|"yes"| chk{"Contradicts an active decision?<br/>a must-link against a cannot-link"}
    chk -->|"yes"| refused["Refused"]
    chk -->|"no"| app[("Append the decision<br/>with author and reason")]
    app --> rerun("Re-run offline from the cache, in seconds<br/>author = analyst, so G3 is skipped")
    rerun --> gates{"Gates pass?"}
    gates -->|"yes"| pub["Published, diff printed:<br/>names the decision"]
    gates -->|"no"| held["held: the decision can't be honoured<br/>e.g. merging two people standing at one AGM"]
    pub --> undo("pennant undo appends a revoke;<br/>nothing is ever deleted")
    undo --> app
    pub --> hist("pennant history: every vote change<br/>for one director and why")

Decisions replay on every run, nightly included: dedup applies must-links and cannot-links, and scoring applies set-facts last, over everything the pipeline found.

11. Caching, logging and the nightly run

Code: core/cache.py, core/db.py, logs.py, calllog.py, scripts/nightly.sh. 

flowchart LR
    subgraph db["pennant.db: append-only by database triggers"]
        cache[("cache<br/>llamaextract: once per notice<br/>ch: until 23:59 that day<br/>web: 7 days")]
        runs[("runs + run_outputs<br/>every run's results")]
        decs[("decisions")]
        mc[("model_calls<br/>every live model call")]
    end
    night(["launchd, 02:00 nightly"]) --> nrun("pennant run --publish, live")
    nrun --> cache
    nrun --> runs
    nrun --> mc
    nrun --> log[("logs/pennant-run-N.log<br/>stage times, errors with tracebacks,<br/>pages, CH requests, AI tokens")]
    runs --> plog("pennant log: what a run did")
    mc --> pcalls("pennant calls: per prompt and model,<br/>or exported as JSONL")

A refetch that returns the same answer only moves the cache row's last_fetched date, so an unchanged night adds no rows and publishes an identical snapshot.
